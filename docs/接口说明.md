# 接口说明

更新时间：2026-11-26  
当前阶段：阶段 4（异常检测与告警）

## 1. 基本信息

- 基础地址：`http://127.0.0.1:8080`
- 数据格式：HTML / JSON
- 字符编码：UTF-8
- 认证方式：当前阶段暂无登录认证，后续如实现登录再补充
- 时间格式：ISO-8601 本地时间字符串

## 2. 页面路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 首页 |
| GET | `/devices` | 设备列表，支持 keyword、type、page |
| GET | `/devices/new` | 新增设备表单 |
| GET | `/devices/{id}` | 设备详情 + 最近检测 + 最近 10 条历史 |
| GET | `/devices/{id}/edit` | 编辑设备表单 |
| POST | `/devices/save` | 保存新增或修改 |
| POST | `/devices/{id}/check` | 页面按钮检测单台设备 |
| POST | `/devices/check-all` | 页面按钮检测全部设备 |
| POST | `/devices/{id}/delete` | 删除设备 |
| GET | `/alerts` | 告警中心，支持 status、level、page |
| POST | `/alerts/{id}/acknowledge` | 页面按钮确认告警 |

## 3. 健康检查

### GET /api/health

正常响应（HTTP 200）：

```json
{
  "status": "UP",
  "application": "network-monitor-system",
  "version": "0.1.0",
  "database": "UP",
  "timestamp": "2026-11-25T21:07:09.1409666"
```

### 4.2 其他设备接口

## 5. 监测 REST API

### 5.1 检测单台设备

**POST** `/api/devices/{id}/check`

- 对指定设备执行一次 Ping。
- 更新设备状态、最近检测时间和最近响应时间。
- 写入一条 `monitor_record`。
- 成功返回 HTTP 200。

响应示例：

```json
{
  "id": 6,
  "deviceId": 3,
  "deviceName": "实验服务器",
  "checkTime": "2026-11-25T21:05:28.072208",
  "reachable": true,
  "responseTimeMs": 0,
  "status": "ONLINE",
  "resultMessage": "收到 ICMP 回复，响应时间小于 1 ms"
}
```

说明：

- `responseTimeMs = 0` 表示 `time<1ms`，不是 0 毫秒的精确测量。
- 离线时 `reachable=false`，`responseTimeMs=null`。
- 设备不存在返回 HTTP 404。

### 5.2 检测全部设备

**POST** `/api/devices/check-all`

按设备 ID 顺序逐个 Ping，返回汇总。检测可能需要数秒，具体取决于设备数量和超时设置。

响应示例：

```json
{
  "total": 4,
  "online": 3,
  "offline": 1,
  "error": 0,
  "checkedAt": "2026-11-25T21:05:28.1343179",
  "results": [
    {
      "deviceId": 1,
      "deviceName": "核心交换机",
      "checkTime": "2026-11-25T21:05:26.121397",
      "reachable": true,
      "responseTimeMs": 2,
      "status": "ONLINE",
      "resultMessage": "收到 ICMP 回复，响应时间 2 ms"
    },
    {
      "deviceId": 2,
      "deviceName": "出口路由器",
      "checkTime": "2026-11-25T21:05:28.014588",
      "reachable": false,
      "responseTimeMs": null,
      "status": "OFFLINE",
      "resultMessage": "请求超时（可能离线或 ICMP 被屏蔽）"
    }
  ]
}
```

> 上面示例只展示 2 条结果，实际返回本次检测的全部设备结果。

### 5.3 分页查询监测历史

**GET** `/api/devices/{id}/records?page=0&size=10`

- 成功返回 HTTP 200。
- 设备不存在返回 HTTP 404。
- 设备存在但无记录时返回空 `content`，不是 404。

响应示例：

```json
{
  "content": [
    {
      "id": 6,
      "deviceId": 3,
      "deviceName": "实验服务器",
      "checkTime": "2026-11-25T21:05:28.072208",
      "reachable": true,
      "responseTimeMs": 0,
      "status": "ONLINE",
      "resultMessage": "收到 ICMP 回复，响应时间小于 1 ms"
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 1,
  "totalPages": 1,
  "first": true,
  "last": true
}
```

### 5.4 最近一条记录

**GET** `/api/devices/{id}/records/latest`

- 有记录：HTTP 200，返回一条监测记录。
- 设备不存在：HTTP 404。
- 设备存在但暂无记录：HTTP 404，标题“暂无监测记录”。

## 6. 告警 REST API

### 6.1 分页查询告警

**GET** `/api/alerts`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `deviceId` | 空 | 按设备 ID 筛选 |
| `status` | 空 | OPEN / ACKNOWLEDGED / RECOVERED |
| `level` | 空 | INFO / WARNING / CRITICAL |
| `page` | 0 | 页码，从 0 开始 |
| `size` | 10 | 每页数量，最大 100 |

响应示例：

```json
{
  "content": [
    {
      "id": 4,
      "deviceId": 2,
      "deviceName": "出口路由器",
      "alertType": "DEVICE_OFFLINE",
      "alertLevel": "CRITICAL",
      "message": "设备连续 3 次 Ping 失败",
      "status": "ACKNOWLEDGED",
      "triggeredAt": "2026-11-26T19:04:49.970821",
      "lastSeenAt": "2026-11-26T19:04:49.970821",
      "recoveredAt": null,
      "acknowledgedAt": "2026-11-26T19:05:47.607043",
      "occurrenceCount": 1
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 1,
  "totalPages": 1,
  "first": true,
  "last": true
}
```

筛选示例：

```text
GET /api/alerts?status=ACKNOWLEDGED&level=CRITICAL
```

### 6.2 查询单条告警

**GET** `/api/alerts/{id}`

- 成功：HTTP 200。
- 不存在：HTTP 404，标题“告警不存在”。

### 6.3 确认告警

**POST** `/api/alerts/{id}/acknowledge`

- `OPEN` → `ACKNOWLEDGED`，写入 `acknowledgedAt`。
- 已经是 `ACKNOWLEDGED`：返回当前记录，不重复修改。
- 已 `RECOVERED`：HTTP 409，不能再次确认。
- 不存在：HTTP 404。

响应示例：

```json
{
  "id": 4,
  "deviceId": 2,
  "deviceName": "出口路由器",
  "alertType": "DEVICE_OFFLINE",
  "alertLevel": "CRITICAL",
  "message": "设备连续 3 次 Ping 失败",
  "status": "ACKNOWLEDGED",
  "triggeredAt": "2026-11-26T19:04:49.970821",
  "lastSeenAt": "2026-11-26T19:04:49.970821",
  "recoveredAt": null,
  "acknowledgedAt": "2026-11-26T19:05:47.607043",
  "occurrenceCount": 1
}
```

### 6.4 告警状态说明

| 值 | 页面名称 | 说明 |
|---|---|---|
| `OPEN` | 未恢复 | 异常仍存在 |
| `ACKNOWLEDGED` | 已确认 | 管理员已确认，异常可能仍未恢复 |
| `RECOVERED` | 已恢复 | 设备在线或延迟恢复正常 |

## 7. 错误响应

REST API 使用 Spring `ProblemDetail` 统一返回错误。

### 7.1 参数校验失败（HTTP 400）

```json
{
  "status": 400,
  "title": "参数校验失败",
  "detail": "请求参数校验失败",
  "instance": "/api/devices",
  "errors": {
    "ipAddress": "IP 地址格式不正确，请输入合法的 IPv4 地址"
  }
}
```

### 7.2 IP 重复（HTTP 409）

```json
{
  "status": 409,
  "title": "IP 地址冲突",
  "detail": "IP 地址已存在：192.168.1.1",
  "instance": "/api/devices"
}
```

### 7.3 设备不存在（HTTP 404）

```json
{
  "status": 404,
  "title": "设备不存在",
  "detail": "设备不存在，ID=999",
  "instance": "/api/devices/999"
}
```

### 7.4 暂无监测记录（HTTP 404）

```json
{
  "status": 404,
  "title": "暂无监测记录",
  "detail": "设备暂无监测记录，设备 ID=3",
  "instance": "/api/devices/3/records/latest"
}
```

### 7.5 告警不存在（HTTP 404）

```json
{
  "status": 404,
  "title": "告警不存在",
  "detail": "告警记录不存在，ID=999",
  "instance": "/api/alerts/999"
}
```

### 7.6 告警状态不允许操作（HTTP 409）

例如确认一条已经恢复的告警：

```json
{
  "status": 409,
  "title": "告警状态不允许该操作",
  "detail": "告警已恢复，不能再次确认",
  "instance": "/api/alerts/2/acknowledge"
}
```

## 8. 状态码汇总

| 状态码 | 含义 |
|---|---|
| 200 | 查询、修改、检测或确认成功 |
| 201 | 新增设备成功 |
| 204 | 删除成功 |
| 400 | 参数或 JSON 格式错误 |
| 404 | 设备、监测记录或告警不存在 |
| 409 | IP 地址冲突，或告警状态不允许当前操作 |
