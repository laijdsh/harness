## 4. MySQL 配置

- Windows 服务名：`MySQL84`
- 启动类型：Automatic（开机自启）
- 服务运行账户：LocalSystem
- 监听地址：`127.0.0.1:3306`
- 数据目录：`D:\dev\mysql-8.4.13\data`
- 配置文件：`D:\dev\mysql-8.4.13\my.ini`
- X Protocol：已关闭，33060 端口不监听
- 字符集：`utf8mb4`
- 业务数据库：`network_monitor`
- 应用账号：`netmon`，只拥有 `network_monitor.*` 权限

密码文件放在项目外：

```text
D:\dev\secrets\mysql-root.txt    # MySQL 管理员密码
D:\dev\secrets\mysql-netmon.txt  # 应用账号密码
```

`D:\dev\secrets` 已设置 ACL，只允许当前 Windows 用户访问。禁止把密码文件复制到项目、
提交到 Git 或截图到论文中。

## 7. 常见问题

### 7.1 `java` 或 `mvn` 找不到

先关闭并重新打开 PowerShell/VS Code，让用户环境变量重新加载。

### 7.2 Maven 显示使用了错误的 Java 版本

检查 `JAVA_HOME` 是否指向 `D:\dev\jdk-21`，然后执行：

```powershell
mvn -version
```

输出中应显示 `Java version: 21.0.13.1`。

### 7.3 MySQL 服务未运行

以管理员身份打开 PowerShell 后执行：

```powershell
Start-Service MySQL84
Get-Service MySQL84
```

### 7.4 8080 端口被占用

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8080
```

找到 `OwningProcess` 后，确认是自己启动的 Java 进程再停止：

```powershell
Stop-Process -Id <PID>
```

### 7.5 Windows PowerShell 写入 Java 文件出现 `\ufeff` 错误

PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 BOM。Java 源文件必须使用
**无 BOM 的 UTF-8**。VS Code 默认保存为无 BOM UTF-8，本项目文件也均为无 BOM。
